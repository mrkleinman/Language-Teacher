## 1. What the app is

- **Language Teacher**: a single-page web app for learning Thai (also Japanese and Mandarin). The site is static, on GitHub Pages / Netlify.
- **Main source:** `dev/tt.jsx`, one React file of about 8 MB. It is too big to paste into a chat; share only the parts you need.
- **AI writer and checker:** Claude Haiku 5.5. Requests go through a small **Google Cloud Run server** (`dev/server/google-cloud-anthropic/`) that holds the Anthropic key. The app has a site access code that is never written anywhere.
- **Daily track:** 30 target words chosen by spaced repetition (5 new, 25 review), each in a 3-line A–B–A mini-exchange, so 90 target lines plus greeting and goodbye lines.
- **Listening track:** one story, about 25 words, written scene by scene.
- **Repo:** `mrkleinman/Language-Teacher`.
  - Work branch: `claude/session-continuation-check-a19meq`.
  - `main` is what's live; Netlify auto-deploys from it.

## 5. Why Daily is stuck around 6.1 (what both reviewers keep saying)

1. **Exchanges contradict themselves.** Line 1 says "the door is open" and line 2 asks "when does it open?". Or "really cheap" is followed by "really expensive". The likely cause is forcing the target word into all three lines, so line 2 ends up asking about what line 1 already stated.
2. **One meaning used three times.** ครึ่ง only as "half price" (never "half an hour" or "half past two"); ตื่น only as "wake at 5"; เปิด only as "the door opens".
3. **Small missing words:** จะ (future), มา (went and came back), ให้, แค่…เอง ("only"), and ตอนนี้ + verb where Thai uses แล้ว.
4. **Cue English** that is ungrammatical or doesn't match the Thai.

The guide fixed reliability but not these. They come from how each exchange is planned, not from Thai rules.

## 6. Recommended next step (not started; waiting for the owner)

**Restructure the exchange plan, keeping Haiku and the guide.** This is a prompt change only, with no new checking layer:

1. Before writing, choose **three different meanings or word pairings** for the target. For example, ครึ่ง: ลดครึ่งราคา / ครึ่งชั่วโมง / สองโมงครึ่ง. เปิด: ร้านเปิดกี่โมง / เปิดแอร์ / เปิดแล้ว.
2. Plan **one small situation** in which each line adds something new. **Line 2 never asks what line 1 already said**, and line 3 never contradicts line 1.
3. One paid test (about US$0.30), then two blind reviews.

**Other options:**
- **Test a stronger model** for the writing only, with Haiku still judging. The server only allows Haiku today (`ALLOWED_MODELS` in `dev/server/google-cloud-anthropic/index.js`), so this needs a code change plus a server redeploy. Writing would likely cost 3–5 times as much.
- **Listening:** the owner is still choosing between a stronger model and set-up/payoff planning across scenes. Don't proceed without the owner.

**Vocabulary decisions already made:**
- รถเมล์ = public city bus.
- พยายาม = try hard.
- สามารถ = formal ("say or ask formally"). Any formal lesson word is used formally, with "formally" in the cue.
- เธอ is practised as "she"; use เขา for "she" in everyday lines; the two friends never call each other เธอ.
- No พี่ as "I".

## 10. How to use a regular Claude chat for this

A regular chat can't run the app or the tests. It's good for:
- **Rating or reviewing a track:** upload the Daily export `.txt` and ask for a blind review with the same five areas (Thai 35%, cues 20%, vocabulary 20%, reading 15%, coherence 10%).
- **Improving the guide or writing prompt text:** paste the relevant section (for example the `_stableSystem` text) and ask for a revised version.
- **Planning:** decide between the options in section 6.

To apply changes to the app, you need Claude Code or a developer with the repo.

## 11. Paid tests on the owner's Windows PC (added 24 Oct)

Claude's cloud workspace cannot reach the Cloud Run server (its network only allows GitHub and package registries), so paid Daily tests now run on the owner's own computer with `dev/sandbox/windows/run-daily-test.ps1`. It is the same runner (`sandbox/live_haiku.js`, owner profile, same caps and ledger).

- First time, in PowerShell: `git clone --depth 1 -b claude/session-continuation-check-a19meq https://github.com/mrkleinman/language-teacher "$HOME\LanguageTeacher\repo"`
- Each test: `powershell -ExecutionPolicy Bypass -File "$HOME\LanguageTeacher\repo\dev\sandbox\windows\run-daily-test.ps1" -Label D15` (add `-CheckOnly` for a free check of the server and the access code).
- The script pulls the latest branch, builds, asks for the access code at a hidden prompt, and writes each run to `$HOME\LanguageTeacher\runs` (outside the repo). The owner backup is the newest `thai-backup-*.json` in `$HOME\LanguageTeacher` or Downloads; earlier exports for the repeat check go in `$HOME\LanguageTeacher\history`.
- A chat linked to that computer can read the runs folder once the owner grants it, then review the export and commit the ledger.
