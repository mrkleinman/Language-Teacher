# Adding Cantonese (`yue`) to the app: spec and checklist

Single-file React app `dev/tt.jsx` (~58.5k lines). Mandarin (`zh`, fields `chinese`/`pinyin`/`english`) is the model; Cantonese is the fourth language after Thai (`th`), Japanese (`ja`), Mandarin (`zh`). The data is finished: `dev/cantonese-modules/` (word list `cantonese-word-base.csv` / `cantonese-word-tags.csv`, 2,995 checked modules in `drafts/ALL-modules.csv`, tools `tools/yue_check.py`, `yue_merge_modules.py`, `yale.py`).

## Decisions (made by the owner's brief; follow them)
- Language code `'yue'`, display name "Cantonese", picker label with the 廣東話 script. Traditional characters, Hong Kong usage. Romanisation = **Yale** (already computed in the word list as `yale`; never Jyutping on screen; no tone numbers).
- Bank row fields: reuse `chinese` for the written form (traditional) and **store Yale in `pinyin`** so the ~228 `pinyin` readers keep working, with a comment at the definition saying "Yale for yue". Add `jyutping` (kept for the voice/debug only, not shown). `id` = the locked id from the word list; `unlockOrder` = `rank` (curriculum position; ids are NOT positions here, like the Japanese bank). Only live rows (`skip` empty) go into the bank: 2,470 words. Belt names and tiers come from the list (`belt`, `tier`).
- Every Mandarin-only code path that handles pinyin tone marks, tone sandhi (`TONE3`, `mandarinSpokenPinyin*`, `v684Zh*`), `validateMandarinPinyin`, Simplified-only text and Mandarin grammar rules must NOT be applied to `yue`. Cantonese spoken form = citation form. Needs a Yale validator (combining marks m̀h, m̄; low tones carry `h`; reject tone numbers).
- First slice = **module-driven Daily with zero model calls** (as for the gap-fill modules of the other languages): bank + registry + module loader/render/exchange + Yale validation + TTS + UI strings + CSS + tests. The model-path fallback, Listening, Gen2 and quality-review screens can show "not available for Cantonese yet" or reuse generic paths when they are language-agnostic; nothing may silently fall through to Thai (the many `lang==='ja' ? … : lang==='zh' ? … : thai` ternaries must each be visited and given a yue branch or an explicit guard).

## (A) Data
- Bank block: new `YUE_BANK begin/end` markers beside `// ══ ZH_BANK` (lines ~3061-6336) holding `RAW_CANTONESE_VOCAB`; generator `dev/tools/build_yue_bank.py` modelled on `dev/tools/build_ja_zh_banks.py` (functions `block()`, `splice()`; first insert needs an anchor). Row: `{id, unlockOrder, chinese, pinyin(=Yale), jyutping, english, partOfSpeech, note?, tier, entryType:'word', curriculumIndex}`; runtime fields are added by an `initCantoneseVocab` twin of `initMandarinVocab` (~6630) / `mergeMandarinVocab` (~6647). There is no phrase data (`YUE_PHRASE_DATA` absent): phrase code reads data defensively with `typeof`.
- Module data: new `// YUE_MODULES_DATA_BEGIN/END` block after the ZH one (~57237-57239), generator `dev/tools/build_yue_modules.py` modelled on `dev/tools/build_zh_modules.py` (gzip+base64, payload `{v:'z1', t:{id:[word,tier,cell,english_slot,english_plural,classifier,classifierYale]}, m:[15-field rows], c:["text\x1fromanisation"]}`; 15-field row `[module_id, cell, tier, excl, A1 items, A1 en, A1 prompt, B items, B en, B prompt, A2 items, A2 en, A2 prompt, scene, job]`). Differences: columns `A1_yue/B_yue/A2_yue`, tag column `classifier`, romanisation per chunk = Yale (use `tools/yale.py` and the word list's `yale`; free particles 呀 啊 啦 喇 囉 嘛 喎 啩 噃 咯 吖 啫 哦 噢 嗯 喂 哎 哇 嘿 哈 and classifier readings need a table), uses `yue_check.py` / `yue_merge_modules.py` functions (names match the Mandarin tools), `--fixture` writes `dev/fixtures/yue-modules-equivalence.json`.
- Tables embedded in code that need a Cantonese twin or an explicit decision: `MANDARIN_GRAMMAR_SCAFFOLD` (~6343; Cantonese grammar words 嘅 咗 唔 冇 喺 …), `MANDARIN_CONVERSATION_BASICS` (~6372), `ZH_COMMON_COMPOUNDS`, `ZH_PARTICLES`, `TEACHING_APPLICATIONS_LANG.zh`, `CC_LANG.zh`, `LEX_FRAMES.zh`, `TP_CLASS_BY_SURFACE.zh`.

Decisions that differ from the text above, with the reason:
- `unlockOrder` / `curriculumIndex` = the list's rank order with its one gap (rank 753) closed (1 … 2470), not the raw rank: the app measures a belt against its required positions, so a belt with a gap could never be completed. Six words at a belt boundary
  (一樣 方法 偷 告訴 速度 規矩) therefore sit one belt earlier than the list's `belt` column says. The last belt holds 295 of its 325 positions (the list is 30 words short of 2,500), so 1st Kyu / Shodan cannot be awarded yet.
- Chunk format of the module data is `word \x1d Yale` pairs joined by `\x1e` (words, not whole-chunk romanisation), so the word-by-word view needs no segmenter; 呢 is read nī before a word and nē at the end of a clause (decided at build time).
- Browser voice: zh-HK, then yue-HK (also zh_HK, zh-Hant-HK); zh-TW is NOT a fallback (it is a Mandarin voice). With no Hong Kong voice no voice is chosen and the Player / dashboard / learn-words screens say the audio may be read in Mandarin.
- 穿 睜 當 have no module: they are not eligible targets (`jazhTargetEligible`, `YUE_NO_MODULE_IDS`), so their belts cannot be completed until they get modules (or a model path). The dashboard says so.

## Model path, stage 1: AI quality review of finished module tracks (17 Nov, done)
Done: after a Daily / Revision module track is built, ONE request judges all its lines (`runCantoneseQualityReview`, `yueReviewPrompt`, strict `yueReviewParse`, schema `GEMINI_SCHEMAS.yueReview`, stage `E_yue_review`, run kind `yue-quality-review`). It follows the model chosen in Settings (the run binds it; `geminiRequest` routes it), through the shared transport, retries, credentials and cost ledger; `aiSelectedModelStatus` says before anything is sent whether that model can be reached (default model: a Gemini key; the optional model: the saved site access code, no Gemini key needed). No key / model: nothing is sent, the screen and the transcript say so, the track can still be studied (the structure check stays the gate); never a fall-back to another model or another language's reviewer. The reviewer only judges (Mandarin-isms and written Chinese, English fidelity, Yale vs characters, target sense, register A man / B woman); Yale and sentences stay as the data has them.
Where: `CantoneseReviewPanel` (runs on its own after a build in `CantoneseGenerator`, or on a button in `CantoneseQualityReview`, the saved-track screen opened by the Player's Review button), `yueApplyReview`, `yueReviewExportLines`. The result is `track.qualityReview` ({status done | not-run | failed, verdict, flags[], requests, costUsd, model, ...}); the usage goes on `track.aiUsage` and the header cost chip. "Quality review" left `YUE_NOT_YET`. Tests: `tests95.js` (model stubbed at the network boundary). Not verified against a live model (none available in the build sessions): the prompt and the flags' usefulness need one real run per model.
Stage 2 (open), reusing the same plumbing: (1) model-WRITTEN Cantonese Daily / Revision for words with fewer than 3 modules or as a top-up: a `buildCantonesePrompt` (Traditional characters, Hong Kong colloquial, Yale NOT asked of the model: Yale built from the segment table + `validateYale`), `generateCantoneseTrack` falling back per target to a model candidate that must pass `yueLineProblems` and then this reviewer (a flagged candidate is rewritten once, then dropped), the shared recall ledger and checkpoint (`GEN_CHECKPOINT_KEYS.yue`); (2) Listening: `listeningAdapterFor('yue')` on the shared Listening core (scene writer + naturalness judge = this reviewer's rules, speaker A man / B woman); (3) Topics: `LANGUAGE_TOPICS.yue` and the shared topics view; (4) Gen2 / the test generator: `gen2Context` for yue after (1) exists. Each step removes its row from `YUE_NOT_YET` and its pins from tests93 with a comment.
