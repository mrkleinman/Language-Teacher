# Adding Cantonese (`yue`) to the app: spec and checklist

Single-file React app `dev/tt.jsx` (~58.5k lines). Mandarin (`zh`, fields `chinese`/`pinyin`/`english`) is the model; Cantonese is the fourth language after Thai (`th`), Japanese (`ja`), Mandarin (`zh`). The data is finished: `dev/cantonese-modules/` (word list `cantonese-word-base.csv` / `cantonese-word-tags.csv`, 2,995 checked modules in `drafts/ALL-modules.csv`, tools `tools/yue_check.py`, `yue_merge_modules.py`, `yale.py`).

## Decisions (made by the owner's brief; follow them)
- Language code `'yue'`, display name "Cantonese", picker label with the 廣東話 script. Traditional characters, Hong Kong usage. Romanisation = **Yale** (already computed in the word list as `yale`; never Jyutping on screen; no tone numbers).
- Bank row fields: reuse `chinese` for the written form (traditional) and **store Yale in `pinyin`** so the ~228 `pinyin` readers keep working, with a comment at the definition saying "Yale for yue". Add `jyutping` (kept for the voice/debug only, not shown). `id` = the locked id from the word list; `unlockOrder` = `rank` (curriculum position; ids are NOT positions here, like the Japanese bank). Only live rows (`skip` empty) go into the bank: 2,470 words. Belt names and tiers come from the list (`belt`, `tier`).
- Every Mandarin-only code path that handles pinyin tone marks, tone sandhi (`TONE3`, `mandarinSpokenPinyin*`, `v684Zh*`), `validateMandarinPinyin`, Simplified-only text and Mandarin grammar rules must NOT be applied to `yue`. Cantonese spoken form = citation form. Needs a Yale validator (combining marks m̀h, m̄; low tones carry `h`; reject tone numbers).
- First slice = **module-driven Daily with zero model calls** (as for the gap-fill modules of the other languages): bank + registry + module loader/render/exchange + Yale validation + TTS + UI strings + CSS + tests. The model-path fallback, Listening, Gen2 and quality-review screens can show "not available for Cantonese yet" or reuse generic paths when they are language-agnostic; nothing may silently fall through to Thai (the many `lang==='ja' ? … : lang==='zh' ? … : thai` ternaries must each be visited and given a yue branch or an explicit guard).

## (A) Data
- Bank block: new `YUE_BANK begin/end` markers beside `// ══ ZH_BANK` (lines ~3061-6336) holding `RAW_CANTONESE_VOCAB`; generator `dev/tools/build_yue_bank.py` modelled on `dev/tools/build_ja_zh_banks.py` (functions `block()`, `splice()`; first insert needs an anchor). Row: `{id, unlockOrder, chinese, pinyin(=Yale), jyutping, english, partOfSpeech, note?, tier, entryType:'word', curriculumIndex}`; runtime fields are added by an `initCantoneseVocab` twin of `initMandarinVocab` (~6630) / `mergeMandarinVocab` (~6647). There is no phrase data (`YUE_PHRASE_DATA` absent): phrase code reads data defensively with `typeof`.
- Module data: new `// YUE_MODULES_DATA_BEGIN/END` block after the ZH one (~57237-57239), generator `dev/tools/build_yue_modules.py` modelled on `dev/tools/build_zh_modules.py` (gzip+base64, payload `{v:'z1', t:{id:[word,tier,cell,english_slot,english_plural,classifier,classifierYale]}, m:[15-field rows], c:["text\x1fromanisation"]}`; 15-field row `[module_id, cell, tier, excl, A1 items, A1 en, A1 prompt, B items, B en, B prompt, A2 items, A2 en, A2 prompt, scene, job]`). Differences: columns `A1_yue/B_yue/A2_yue`, tag column `classifier`, romanisation per chunk = Yale (use `tools/yale.py` and the word list's `yale`; free particles 呀 啊 啦 喇 囉 嘛 喎 啩 噃 咯 吖 啫 哦 噢 嗯 喂 哎 哇 嘿 哈 and classifier readings need a table), uses `yue_check.py` / `yue_merge_modules.py` functions (names match the Mandarin tools), `--fixture` writes `dev/fixtures/yue-modules-equivalence.json`.
- Tables embedded in code that need a Cantonese twin or an explicit decision: `MANDARIN_GRAMMAR_SCAFFOLD` (~6343; Cantonese grammar words 嘅 咗 唔 冇 喺 …), `MANDARIN_CONVERSATION_BASICS` (~6372), `ZH_COMMON_COMPOUNDS`, `ZH_PARTICLES`, `TEACHING_APPLICATIONS_LANG.zh`, `CC_LANG.zh`, `LEX_FRAMES.zh`, `TP_CLASS_BY_SURFACE.zh`.

## (B) Logic needing a Cantonese twin (first slice marked ★)
- ★ Registry/storage: `LANGS` (~8679), `LANG_KEY`, a `YUE` storage namespace beside `ZH` (~3035: vocab, tracks, dailyNew), `GEN_CHECKPOINT_KEYS` (~8231) and the `stTabSweep([...])` list (~49199), `GENERATOR_VERSIONS`, `TRACK_LANGUAGES`, `LANGUAGE_NAMES`, `LISTENING_LANGS`, `TRACK_ADAPTERS` (~33143), `LISTENING_ADAPTERS` (~33524), `JAZH_QC_DISPATCH`, `GEN2_LANG`, `CONVO_TTS`, `TT_BENCH_FIELD`, `LANGUAGE_TOPICS`. Multi-tab sync (`stSync*`, `useTabSyncedList`) is generic by storage key; copy the wiring in `MandarinTeacher` (~58281-58308). `AppRoot` (~58515) language normalisation `saved === 'ja' ? … : saved === 'zh' ? … : 'th'` and component choice; `onSetLang`.
- ★ Segmentation/validation: `segmentMandarin`/`mandarinLexicon` take the lexicon as a parameter (default `RAW_MANDARIN_VOCAB`) so a `yue` lexicon can reuse the DP; a Yale validator; a pair validator for modules lines using the list in `dev/cantonese-modules/tools/yue_check.py` (`MANDARIN`, `BANNED`, `FORMAL`, `FINAL_PARTICLES`, `FREE`, units/length ranges) — the build-time checker already guarantees the module lines, so the runtime check can be the shared structural checks (no leftover token, segments rebuild the sentence, Yale matches).
- ★ Modules loader/render (copy `zhModules*` ~57240-57360 → `yueModules*`): `yueModulesSetEnabled/UseData/Load/Active/BeginRun`, `yueModuleTagOf`, `yueModuleCandidates`, `yueModuleChunk`, `yueModuleRender` (romanisation joined with `tidyPinyin`; check it does not damage Yale combining marks), `yueModuleExchange`; reuse `jaModuleLearnerTier`, `jaModuleFillEn`, `JA_MODULE_TIER_OF_BELT`. Daily generation: `generateMandarinTrack` (~8301) / `generateMandarinOneRecall` (~7959) module hook (`o.moduleLine`) → a `generateCantoneseTrack` that is module-only when the model is not needed.
- ★ TTS: `TTS_VOICES` (~3013), `ttsVoiceFor`, `pickBrowserVoice` (the `slice(0,2)` fallback would give `yu`; match `zh-HK`, `yue-HK`, `zh-TW` order explicitly and never fall back to a mainland Mandarin voice silently if a HK voice exists), `CONVO_TTS` (`prefix:'zh'` also matches Mandarin voices), `Player` `_tlCode`/`speechTextOf` (~43386-43396), `ttsTextForPair` (~27828) and `ttsTextForWord` (~27889): speak the Traditional characters with language tag `yue-HK`/`zh-HK`.
- Later: `buildMandarinPrompt`-style model prompts (must say Traditional characters, Hong Kong colloquial, Yale), Listening adapters, Gen2, quality review, cue helpers.

## (C) UI
- ★ `LanguageSelector` loops `Object.values(LANGS)` (new entry appears), `Header`, `MandarinTeacher` / `MandarinDashboard` twins (`CantoneseTeacher`/`CantoneseDashboard`, ~58159-58420; footer text, loading text, delete-track strings), `WordListView`, `BeltRankView`/`BeltRankCard` (`beltAbilityFor(lang)`, `BELT_ABILITIES.zh` ~12859 → Cantonese abilities with Yale text), `RankTestView` head ternary, `DAILY_NEW_WORDS_MUKYU` (~13447, `{th:3, ja:3, zh:5}` → yue:5) and `getNewWordLimitForBelt`, `Player` `_tl==='zh'` branches (labels "Say in Cantonese", segment renderer showing `s.pinyin` = Yale), `NonThaiExtraView` name ternary, `MandarinTargetPill`, `downloadMandarinTrack`, `MandarinLearnWords` (hard-coded `zh-CN`).
- ★ CSS: line ~25 `.zh` / `:lang(zh)` uses a Simplified Chinese stack; Cantonese needs a Traditional/HK stack (Noto Sans HK, PingFang HK, Microsoft JhengHei) via `className="yue"` / `:lang(yue)`/`zh-HK`.

## (D) Build and tests
- Build: `node build.js tt.jsx tt.compiled.js`; release procedure is the owner's (do NOT release): `python3 build_index.py tt.jsx build/index-1.shell.html /tmp/rel_out/index.html vNNN; node check_sync.js tt.jsx /tmp/rel_out/index.html`.
- Tests enumerate languages: hard-coded `['th','ja','zh']` in tests14, 15, 21, 23-29, 34-37, 43, 46, 49, 54, 55, 58, 73, `render_test.js`, `sim_live.js`, `fuzz_listening_scenes.js`, `browser_checks_v672.js`; objects keyed th/ja/zh in tests14, 21, 24, 26-28, 36, 45, 46, 49, 54, 58; tests using `TRACK_ADAPTERS`, `LISTENING_ADAPTERS`, `getNewWordLimitForBelt`: tests14, 15, 21, 28, 29, 34, 36, 43, 46. Extend them for `yue` where the language is part of a generic loop (do NOT weaken or special-case a test to hide a defect; explain every test change in a comment in the test file). `run_all.sh` lists suites explicitly: add new ones. Mandarin-only suites to mirror for Cantonese: tests84 (particles/complexity), tests86 (module equivalence vs `fixtures/zh-modules-equivalence.json`; asserts module counts), tests90 (cues), tests77/78 (bank, phrase split, start gate), tests73 (dashboards). Add `yueModulesSetEnabled(false)` to `harness.js` next to the Thai hook for model-path tests.

## Standing rules (from the owner)
- Never put an API key anywhere in index.html, committed JS, localStorage or public assets; never ask the user to paste a key or access code; the LT_ACCESS code is never written to any file/log/export/commit.
- No model identifiers in commits or code comments (tests13 scans for them). Plain words in reports; every report ends with a TL;DR.
- Do not stash/checkout/reset on the shared tree; commit and push regularly to branch `claude/session-continuation-check-a19meq` with the two trailer lines the harness gives; do not open a PR; do not release (the owner's session releases).
- Do not adjust tests to hide a defect.
