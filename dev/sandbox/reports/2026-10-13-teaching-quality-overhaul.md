## 2. Changes and files

All code in `dev/tt.jsx`, built as **v690** (= v689 belts + these changes). Tests: `dev/tests47.js` (new), `dev/run_all.sh`.

**One switch.** Every change below sits behind `oct13On()` (ON in the app, never stored). With it OFF the build behaves exactly like v689; the old replay guards (tests37 C1, tests39 A5, tests45 P1–P3, `rc_replay_check.js`) now run with it off, which proves nothing ELSE changed, while tests47 checks the changes themselves with it on (S2 checks that off really restores the old behaviour). The lost-connection retry is a transport fix and is not switched.

| Area | Change | Function(s) |
|---|---|---|
| Lost connections | HTTP 200 without a readable body = lost connection: retried like a network error (3 tries); after the last try only that request fails, non-fatal, nothing latched. A real malformed reply is still a failed candidate. | `anthropicRequest` |
| Judge retry | A failed judge REQUEST is asked once more (cancellation / fatal provider errors still stop). | `aiQcEvaluateGroup` |
| Slot-only repair | Judge returns `problems` (1-based lines); only a proper valid subset narrows repair; repair prompt shows the whole group and asks to rewrite only those lines; an unrecoverable verdict rejects only those slots. No line named → old whole-group behaviour (fail closed). | `aiQcEvaluateGroup`, `aiQcProblemSlots`, `runAiQualityCheck`, `aiQcRegenerateGroup`, `GEMINI_SCHEMAS.groupVerdict` |
| One permission contract | Recovery QC gets `authorisedKeywords: track.keywords`; both QCs build the inventory from `authorisedKeywords \|\| keywords`. | `_jaRecoverTargetPairs`, `_zhRecoverTargetPairs`, `runJapaneseTrackQC`, `runMandarinTrackQC` |
| Recovery placement | Removed pairs' position and speaker are remembered; recovered pairs return after the line that preceded the removed group; Japanese ones take the replaced pair's speaker. | `enforceTrackPairQuota`, `_quotaInsertAt` |
| Punctuation segments | A segment that is only punctuation is punctuation. | `runMandarinQualityCheckCore` |
| Cue addressee | Deterministic: the speaker's own name in an addressing position ("Tell / Ask / Suggest to … X") becomes the other character's name; he/she in that cue follow the addressee's gender. Runs on the final track before the text freeze. | `fixCueAddressees`, `finaliseMainTrack` |
| Japanese romaji | Final romaji rebuilt word by word from the final sentence when the dictionary reading agrees with the sentence's reading; else model romaji kept with punctuation/spacing tidied (ASCII ?.!, da yo, mata ne, kamo, を = o). | `jaFinalRomaji`, `jaTidyRomaji`, `_jaFinaliseMetadata` |
| Mandarin spoken tones | Tone sandhi decided per syllable (words keep their spacing); 不 and 3+3 rules unchanged otherwise. | `mandarinSpokenPinyin` |
| Mandarin framing | 你好 → 你好, 再见 → 再见 (嗯 only if the bank lacked them). | `mandarinFramingPairs` |
| Thai phonetics | ɔi → awy, ɔɔi → aawy (as the app's own ráawy / náawy); ลอง typo → laawng. Display conversion only; stored dictionary untouched. | `fixIPAPhonetic`, `loadCanonicalThaiPhonetic` |
| Thai spelling | ที่นั้น rejected with ที่นั่น named (so repair writes ที่นั่น, which must itself pass the learner's vocabulary). | `thaiQcCheckSpelling`, `runThaiQcChecks` |
| Thai commas | The contradictory "add commas" rule replaced by "a space marks the pause"; commas left in final text become a space before the freeze. | `generateWordLines` prompt, `thaiTidyCommas` |
| Naturalness guidance | Thai guide (writer + native reviewer) and Mandarin guide with the brief's examples, as patterns with the natural form — no blacklist. Group judge now judges each line IN CONTEXT. | `THAI_NATURALNESS_GUIDE`, `ZH_NATURALNESS_GUIDE`, `aiQcEvaluateGroup` |
| Vocabulary-aware stages | Soft stages <100 / 100–299 / 300–699 / 700+ in all three writers; every stage restates the absolute contract. | `VOCAB_STAGES`, `vocabStagePromptRule` |
| Labels & cost | Provider names from what the run used; "Generated by" uses the generation model; COST PER ACCEPTED RECALL line. | `trackGeneratedByLine`, `aiProvidersUsed`, `aiCostPerAcceptedRecall`, `aiUsageExportLines` |

## 7. Grading / acceptance rule changes

- **No acceptance threshold was lowered.** 90/90, closed vocabulary, target presence, register, final audit and "UNVERIFIED is never READY"
  are unchanged.
- **Stricter:** ที่นั้น (for "there") is now a rejection; the group judge now fails a correct sentence that does not fit its moment.
- **Narrower rejection:** an unrecoverable verdict that names its line rejects only that line (the other two valid sentences count).
- **Recovery QC** now checks against the same words the sentence was generated with (the whole track) — this is consistency, not
  loosening: those words were always authorised for the track.
- Absolute vs adaptive:
  - **Absolute (every learner, every stage):** 3 recalls per target; complete, grammatical, natural sentences; target present in its intended
    sense; closed vocabulary; correct register and speaker; cue that leads to the sentence; correct pronunciation; 90/90 for READY.
  - **Adaptive (by vocabulary size):** how different the three constructions must be. Under 100 words repetition of one useful pattern is
    good teaching; 100–299 vary situation or speaker where natural; 300–699 prefer three different uses; 700+ expect clear variety.
    This steers the writer only — it never accepts or rejects a sentence.

## TL;DR
The 13-Oct problems came mostly from the pipeline, not the model: dropped phone connections treated as bad answers, recovery checking
words against the wrong list, whole groups thrown away for one bad line, cues written before speakers were swapped, a Thai prompt that
asked for commas, and pronunciation tools that split syllables or misread tones. All of those are fixed on the dev branch with 43 new
offline checks. Sentence naturalness got clearer rules for the writer and the judge, but 8/10 can only be proven with a live test
(≤ US$0.60, your approval needed). Nothing is deployed.
